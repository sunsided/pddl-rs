# pddl-runtime

The planning-task trait and the fact storage that code generated from PDDL
(by [`pddl-codegen`](https://github.com/sunsided/pddl-rs/tree/main/pddl-codegen), through the `pddl` crate's
`codegen` feature) builds on. It has no dependencies and does not depend on the
PDDL parser.

Part of the [planning and search crates](https://sunsided.github.io/planning-and-search/).

- `Task`: initial state, successors, goal test and action costs. Planners are
  generic over it and monomorphize per domain; there is no `dyn` on the hot
  path.
- `Id`, `BitSet`, `BitRelation`, `BitTable`: facts of predicates of any arity,
  over typed object ids, cheap to clone and hash.
- `Values`: numeric fluents, hashable.
- `Formula` and `Expr`: ground goals that a task evaluates at run time.
- With the `search` feature: blind breadth-first search, A* and IDA*, and plan
  replay. These are reference searches for tests and benchmarks.

## Who this is for

- Authors of planners or search code who want to run on tasks generated from
  PDDL by `#[pddl::task]`, through the `Task` trait.
- Anyone who writes a planning task by hand and wants compact, hashable fact
  storage for its states.
- Code generated by `pddl` already gets this crate as `pddl::runtime`; add it
  directly only for code that is generic over `Task`. For full-featured
  heuristic search over your own graph, see
  [`heuristic-search`](https://github.com/sunsided/heuristic-search).

## Installation

```toml
[dependencies]
pddl-runtime = { version = "0.1", features = ["search"] }
```

Leave out `search` if you bring your own planner.
